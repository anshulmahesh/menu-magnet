Setup, mapping and customization.

This guide describes the bundled Menu Magnet Lua implementation, extracted from the supplied Hammerspoon configuration. The website is an illustration; the Lua engine runs locally on macOS.

Prerequisites

Menu Magnet is a Hammerspoon Lua script, not a standalone macOS app or a browser extension. The base magnetic-scrolling interaction does not require changes to macOS native gesture mappings or additional key-mapping software.

Hammerspoon relies on the Accessibility system. Applications that do not publish standard AXMenu and AXMenuItem objects may not be navigable with Menu Magnet.

Optional hardware haptics

For supported Force Touch trackpads, install mactic using its documented Homebrew tap:

brew install matmercer/tap/mactic
mactic -w 1

Menu Magnet looks for the executable at /opt/homebrew/bin/mactic (Apple silicon Homebrew) or /usr/local/bin/mactic (common Intel Homebrew path). Other paths require editing MACTIC_PATH detection in the script. If it is unavailable, the configured system-sound fallback can play instead. The mactic project uses a private Apple framework; compatibility can change after macOS updates.

Installation

  1. Install Hammerspoon, open it and grant Accessibility permission when prompted. Relaunch it if macOS requests that.
  2. Download the MenuMagnet.lua file from this website (the same engine is under src/MenuMagnet.lua in the repository) and put it in ~/.hammerspoon/.
  3. Open your existing ~/.hammerspoon/init.lua (create it if missing). Add the one-line loader below.
  4. Reload Hammerspoon. Test a standard native app menu, such as File in Finder, or a context menu.
-- Add this line ONCE to ~/.hammerspoon/init.lua:
dofile(hs.configdir .. "/MenuMagnet.lua")

Your Hammerspoon folder should look like:

~/.hammerspoon/
├── init.lua                # Your existing config + loader
└── MenuMagnet.lua          # The Menu Magnet engine
Do not replace your whole existing init.lua. The supplied file originally bundled unrelated automations. This public package contains just Menu Magnet; install it as a separate file and load it from your existing setup. Also remove any older Menu Magnet loader calls to avoid simultaneous event taps.

Important: This source explicitly calls hs.menuIcon(false), hiding the normal Hammerspoon menu bar icon. You can comment that line out if you want Hammerspoon’s native menu icon to remain visible. The script’s own showMenuBarItem setting defaults to false.

First run

Click the macOS menu-bar item File or open a standard right-click context menu. Release the click, then use two fingers to scroll. The active highlight should move between rows. If not, use the diagnostic steps below.

Native macOS gesture mapping

Most default trackpad settings can stay untouched. Menu Magnet listens to native secondary-click and scroll events while a supported menu is open; it does not globally remap four-finger swipes or force macOS to disable its gestures.

If you choose to enable the experimental three-finger input, review Trackpad → Point & Click and Accessibility → Pointer Control → Trackpad Options for competing macOS gesture features first.

Using Menu Magnet

Context menus

  1. Secondary-click an item (two fingers, by default).
  2. Release the click — holdSecondaryClick = false is the bundled default.
  3. Two-finger scroll up or down. The pointer snaps between eligible menu items and feedback triggers per step.
  4. Click a command normally to activate it, or leave the menu to disengage.

App menu-bar dropdowns

Click File, Edit, View or another accessible application menu. Scroll vertically to move through items. Menu Magnet avoids accidental top-menu switching caused by diagonal trackpad movement.

Submenus

On a menu item with a submenu, use a normal primary click or a secondary click while the menu is already open. Menu Magnet watches for the native submenu and attaches to it. The secondary-click shortcut is guarded so it only applies when an accessible submenu is known or visible.

Edge escape

Within a submenu, scroll to the first or last item, lift your fingers, and scroll again in the same direction after a short gap. With the bundled settings, Menu Magnet returns to the root menu and advances a root item. This is different from a normal single long scroll gesture, which should stop at the edge.

Velocity flicks

A fast two-finger scroll can jump several rows, limited by maxJump. Movement is paced by stepIntervalMs. Momentum scroll events are swallowed while the menu is active to reduce overshoot.

Suggested profiles (manual edits)

The bundled script has one active configuration table; these are example settings, not a built-in profile switcher.

-- Precise, calm
scrollThreshold = 18,
velocityScrolling = false,
maxJump = 1,
hapticWaveform = 1,

-- Responsive, fast
scrollThreshold = 10,
velocityScrolling = true,
velocitySensitivity = 70,
maxJump = 3,
stepIntervalMs = 35,

For reliable immediate cursor placement, leave verticalSmoothingFrames = 0. If scrolling runs backward relative to your preferred trackpad direction, flip invertScroll. Do not change unrelated macOS gesture settings simply to adjust navigation direction.

Troubleshooting

Nothing happens after scrolling a menu

Confirm Hammerspoon Accessibility permission, then reload Hammerspoon. Test a normal Finder File menu. Set debugAX = true, reload, and inspect the Hammerspoon Console. Unsupported custom-drawn menus may not expose accessible rows.

Scroll direction is reversed / sensitivity feels wrong

Switch invertScroll. Increase scrollThreshold for fewer detents, or decrease it for more sensitivity. Adjust velocitySensitivity and maxJump to prevent large jumps.

Haptic clicks do not happen

Make sure mactic -w 1 succeeds on your hardware and the executable is in one of the two paths the script checks. Confirm hapticEnabled = true. On unsupported devices, use the sound fallback. Since mactic uses private APIs, macOS updates can break it independently of Menu Magnet.

Click opens submenu unexpectedly / two-finger interaction feels awkward

Set twoFingerClickEntersSubmenu = false if you want to rely only on native left-click submenu entry. Default holdSecondaryClick = false means the original secondary click is released before scrolling; do not hold it while testing the standard workflow.

Gestures conflict with macOS

The default code does not remap four-finger swipes. Keep threeFingerBack = false until you deliberately test that experimental feature. Do not disable system swipes globally as a first troubleshooting step.

My Hammerspoon menu bar icon disappeared

The Lua file calls hs.menuIcon(false). Comment out that line and reload if you want the original Hammerspoon icon visible. Enabling showMenuBarItem instead adds Menu Magnet's own optional status item.

Another automation stopped working

Load Menu Magnet once, from your existing init.lua. If another automation intercepts the same scroll/click events, only one can effectively own the active gesture at a time. Test with competing event taps disabled before editing native macOS settings.

Compatibility & limitations

  • Menu navigation depends on macOS Accessibility and the target application's menu implementation. Not all apps expose standard menu items.
  • Only menu interactions are included. Finder-list and Apple Music-list extensions are not part of this extracted engine.
  • The Gesture Studio’s touch trails and synthesized clicks are illustrative; browser audio does not trigger the Mac’s haptic actuator. Its long-coast animation is an intentionally expanded representation of velocity scrolling. The Lua engine has maxJump = 3 by default and consumes momentum scroll-wheel events.
  • Experimental three-finger gesture support is disabled by default and may interact with existing macOS settings.
  • The source was provided as-is and extracted without modifying Menu Magnet's logic. It has not been validated on your Mac or across macOS releases in this environment.
  • The code uses system-level event taps and moves the pointer; test with non-critical applications before relying on it.
